# guess-game

Два режима детской игры: «Угадай слово» и «Нарисуй — ИИ угадает».
В игре со словами ответы — «да», «нет» и «не знаю».
Обычная партия — 10 вопросов, для сложных слов — 15. Попытка угадать: «Это кошка?».
Когда остаётся не больше трёх вопросов, игра может показать подсказку о категории.

Ссылка на игру: https://guess-game-utl.pages.dev/

## Структура

- `public/index.html` — интерфейс, CSS и управление игрой со словами без сборки.
- `public/drawing.js` — полотно, инструменты и управление режимом рисования; браузерный ES Module.
- `shared/rules.js` — словарь, признаки, сложность, распознавание вопросов.
- `shared/store.js` — общее хранилище игр: память или Upstash Redis.
- `shared/ai.js`, `shared/prompts.js`, `shared/config.js` — клиент OpenRouter, инструкции и лимиты по задачам.
- `shared/game.js` — создание партии и обработка хода.
- `shared/hints.js` — выбор безопасного направления подсказки.
- `shared/analysis.js` — статистика партии и проверка ответа ИИ для разбора.
- `shared/drawing.js`, `shared/image-input.js` — распознавание рисунков, подтверждение и проверка PNG.
- `shared/adapters.js` — адаптеры Node.js и Cloudflare Pages к общей логике.
- `api/` — точки входа Node.js; `functions/api/` — точки входа Pages Functions.
- `dev-local.js` — сервер Node.js для локального запуска, Render и Docker.
- `tests/` — автоматические проверки без обращений к внешним сервисам.

Весь серверный код использует ES Modules. Игровые правила общие для обеих платформ.
Доступны оба режима, подсказки по кнопке и разбор завершённой партии со словами.

## Рисование

Режим выбирается на первом экране или кнопками над игрой. Полотно поддерживает мышь, палец и перо.
Доступны выбор цвета и толщины линии, ластик, отмена последнего штриха и очистка.
Кнопка «Угадай» отправляет текущий рисунок в ИИ; каждый штрих отдельно не отправляется.
Пустое полотно, в том числе полностью стёртое, не отправляется: браузер проверяет пиксели перед запросом.

ИИ предлагает до трёх вариантов и при необходимости задаёт уточняющий вопрос.
Игрок нажимает «Угадал!» или «Не угадал». После отказа можно дорисовать и повторить попытку;
после подтверждения нужен «Новый рисунок». Если рисунок изменён, старое предположение подтвердить нельзя — нужно отправить обновлённый рисунок.
Во время запроса редактирование, новая партия и переключение режимов заблокированы.
При сетевой ошибке рисунок и предыдущие предположения остаются на странице.

Переключение режимов сохраняет текущий рисунок и партию со словами в памяти страницы.
Перезагрузка страницы их не восстанавливает. Новый рисунок очищает только режим рисования.
Подсказки и аналитика вопросов относятся к игре со словами.

Для распознавания нужен настроенный ИИ: ключ облачного API или работающая Ollama. Модели закреплены в `shared/config.js`: OpenRouter — `nvidia/nemotron-3.5-super-vl:free`, Ollama — `gemma4:e2b`.
Она должна принимать изображения. Модель получает только PNG и инструкцию распознавания: секретного слова у партии с рисунком нет.
Изображение передаётся в `image_url` как data URL через `/chat/completions`;
формат описан в [руководстве OpenRouter по изображениям](https://openrouter.ai/blog/tutorials/send-image-to-llm/).
Ответ ожидается в виде JSON `{ "guesses": ["кошка"], "question": null }`.
При неопределённом рисунке допустим пустой список вариантов с непустым уточняющим вопросом.
Сервер проверяет структуру и длину ответа, но качество распознавания требует отдельного испытания на реальных рисунках.

Приложение хранит в Redis только последнее предположение, ответ игрока и число попыток. PNG в Redis не записывается.
Полотно экспортируется в PNG размером 800×600. Сервер проверяет сигнатуру, структуру контейнера и размеры:
до 1 МиБ, не более 1024×1024, 8-битный RGB/RGBA без чересстрочной развёртки.
Это проверка формата, а не полное декодирование пикселей или проверка CRC. Изображения по внешним URL не принимаются.
Размер входного JSON ограничен 1,5 МиБ в Node.js-сервере и Pages Functions.

| Запрос | Тело | Результат |
|---|---|---|
| `POST /api/new` | `{ "mode": "drawing" }` | Новая партия с `gameId` без секретного слова |
| `POST /api/draw` | `{ "gameId": "...", "imageDataUrl": "data:image/png;base64,..." }` | Последнее предположение `latestAttempt`, `attemptsUsed`, `over` |
| `POST /api/confirm` | `{ "gameId": "...", "attemptId": "...", "guessed": true }` | Подтверждение последнего предположения; `false` позволяет дорисовать |

Невалидное изображение или тело — HTTP 400, превышение размера — HTTP 413, отсутствующая партия — HTTP 404.
Несовпадение режима, устаревшее подтверждение и конфликт параллельных запросов — HTTP 409.
Ошибка ИИ или Redis — HTTP 503; неуспешная попытка не увеличивает сохранённый счётчик.
Повтор идентичного подтверждения безопасен. Запоздавший ответ модели не может отменить уже подтверждённое завершение.

## Подсказки

Кнопка «Подсказка» предлагает направление следующего вопроса. На партию доступно две подсказки;
они не уменьшают остаток вопросов. Под кнопкой видны счётчик и все полученные подсказки.
После окончания партии кнопка недоступна, а при новой игре список и лимит сбрасываются.
Существующая автоматическая подсказка о категории в конце партии сохранена отдельно от этого лимита.

Для подсказок нужен настроенный ИИ: ключ облачного API или работающая Ollama. Используется модель, закреплённая для провайдера в `shared/config.js`.
ИИ получает секретное слово, полную историю и предыдущие подсказки, затем выбирает направление из предложенных сервером.
Сервер исключает уже проверенные признаки, равнозначные им направления и ранее предложенные подсказки.
Модель возвращает JSON с ключом направления; пользователю показывается только готовый текст сервера.
Это не позволяет ответу модели раскрыть слово или вставить произвольный текст в подсказку.

Если ИИ недоступен, исчерпана квота, ответ некорректен или сохранение не удалось,
подсказка не возвращается как успешная и можно продолжить обычную игру. При потере сети после сохранения
следующий успешный запрос получает актуальный список подсказок с сервера.

`POST /api/hint` принимает `{ "gameId": "..." }`. Ответ содержит `hints` (список текстов),
`hintsUsed`, `hintsLeft`, `hintLimit`, а также текущее состояние партии.
Повтор после исчерпания лимита или окончания игры возвращает HTTP 409, ошибка ИИ или Redis — HTTP 503.
Неверный `gameId` — HTTP 400, отсутствующая партия — HTTP 404. Клиент не может изменить лимит в запросе.

## Разбор после игры

После победы или окончания вопросов появляется раздел «Разбор игры» с кнопкой «Разобрать игру».
Статистика показывается сразу: число вопросов, подсказок, повторов и ответов «не знаю».
Повторами считаются одинаковые нормализованные вопросы и вопросы об одном распознанном признаке.
ИИ готовит четыре части:

- Что получилось хорошо.
- Полезный вопрос с объяснением; цитата и ответ берутся из реальной истории по номеру хода.
- Что попробовать иначе, в том числе как избежать повторов.
- Пример вопроса для следующей партии.

Сервер проверяет структуру ответа, длину текста и существование выбранного хода.
Вопрос с ответом «не знаю» или обнаруженным несоответствием не может стать лучшим.
При противоречиях между ответами на один признак или расхождении со встроенными правилами
в интерфейсе появляется пояснение, что возможная ошибка игры не считается ошибкой игрока.
ИИ получает эту информацию вместе с инструкцией не обвинять игрока. Если надёжного вопроса нет,
разбор может обойтись без выделения лучшего вопроса.

Статистика рассчитывается кодом. ИИ получает всю историю, секрет, результат партии и использованные подсказки;
его рекомендации не являются объективной оценкой способностей ребёнка. Текст отображается как текст, без исполнения HTML.

Для генерации нужен настроенный ИИ: ключ облачного API или работающая Ollama. Используется модель, закреплённая для провайдера в `shared/config.js`.
Готовый разбор сохраняется в партии на срок её жизни. Повторный запрос возвращает сохранённый результат,
в том числе если ключ ИИ больше не настроен. В интерфейсе можно скрывать и открывать разбор без дополнительных запросов.
Новая игра сбрасывает отображение предыдущего разбора.

`POST /api/analysis` принимает `{ "gameId": "..." }` и возвращает `{ "analysis": { ... }, "cached": false }`;
при повторном чтении `cached` равен `true`. Пока партия не окончена, запрос получает HTTP 409 без раскрытия секрета.
Некорректный идентификатор — HTTP 400, отсутствующая партия — HTTP 404; пустая история — HTTP 409.

Одновременные запросы используют сохранённую отметку о подготовке разбора. Второй запрос получает HTTP 202
с `pending: true`; кнопка «Проверить разбор» позволяет открыть результат позже.
Если обработчик остановился, отметка разрешает новую попытку через 30 секунд.
Проверка версии не позволяет запоздалому ответу перезаписать более свежий разбор.
При ошибке ИИ, квоте или неверном JSON возвращается HTTP 503 без сохранения неудачного результата;
обычные поля партии и результат игры не меняются. Если очистить отметку после сбоя хранилища не удалось,
повторная генерация станет доступна после истечения 30 секунд.

## Локальный запуск

Нужен Node.js 22 или новее. Внешних npm-зависимостей и шага сборки нет.
Node.js 22 также указан в `.node-version`, Dockerfile, Render и CI.

```powershell
npm start
```

Открыть `http://localhost:3000`. Если порт занят и `PORT` не задан, сервер пробует `3001`.
Без ключа OpenRouter работают встроенные признаки и попытки угадать; остальные вопросы получают «не знаю».

Пример настройки в PowerShell:

```powershell
$env:STORE_KIND = "memory"
$env:OPENROUTER_API_KEY = "<ключ OpenRouter>"
npm start
```

Шаблон настроек — `.env.example`. Если файл `.env` есть в корне проекта, сервер автоматически
загружает его при запуске. Отсутствие `.env` не мешает запуску; переменные из оболочки или хостинга имеют приоритет.
Для работы без ИИ достаточно `npm start`; ключ сейчас добавлять не требуется.
Позже можно скопировать шаблон, заполнить настройки и перезапустить сервер:

```powershell
npm start
```

`.env`, `.dev.vars` и их локальные варианты исключены из Git. `.env.example` хранится в репозитории.

## Локальный ИИ через Ollama

Приложение отправляет запросы уже работающему серверу Ollama. Оно не запускает Ollama, не скачивает модели и не управляет ими.
Для локального режима достаточно настроек в `.env`:

```dotenv
AI_PROVIDER=ollama
STORE_KIND=memory
OPENROUTER_BASE_URL=http://127.0.0.1:11434/v1
```

Для всех задач Ollama используется `gemma4:e2b`; она должна быть установлена и доступна локальному серверу.
`OPENROUTER_API_KEY` локальной Ollama не требуется: приложение подставляет служебное значение `ollama`.
Чтобы сменить модель, нужно изменить константу `OLLAMA_MODEL` в `shared/config.js`.
После изменения `.env` перезапустить `npm start`.

При `AI_PROVIDER=auto` (по умолчанию) адрес на порту `11434` или хосте `ollama` автоматически включает профиль Ollama.
Поэтому существующая настройка с `OPENROUTER_BASE_URL=http://127.0.0.1:11434/v1` работает без новых переменных.
Для Ollama за прокси на другом порту нужно явно задать `AI_PROVIDER=ollama`.
При запуске backend внутри Docker адрес Ollama на Windows-хосте обычно задаётся как `http://host.docker.internal:11434/v1`.

В локальном профиле отправляется `reasoning_effort: "none"` вместо `reasoning.enabled: false`:
иначе у Gemma с включёнными по умолчанию рассуждениями весь лимит может уйти до появления конечного ответа.
Для подсказок, аналитики и рисунков передаётся `response_format` с JSON-схемой;
ключ подсказки ограничен доступными направлениями, ссылки в разборе — допустимыми ходами.
Приложение дополнительно проверяет результат после генерации.
У OpenRouter сохраняются прежние параметры запросов.

HTTP 200 сам по себе не означает, что получен пригодный ответ: `finish_reason: "length"` считается обрывом,
пустое содержимое — некорректным ответом. Для Ollama сервер выводит только задачу и код ошибки,
без ключей, секрета, изображения и текста рассуждений, например `[ai:hint] provider=ollama code=truncated_response`.
Таймауты — 9 секунд для вопросов/подсказок и 15 секунд для аналитики.
Для рисунков Ollama получает до 30 секунд, включая загрузку модели; облачный API — до 15 секунд.
Обрезанный ответ, неверный формат и таймаут показываются как разные ошибки сервиса,
не расходуют попытку и не требуют перерисовывать изображение. Код возвращается в поле `code` ответа API.
Ошибки проверки содержимого JSON также попадают в безопасный лог Ollama.

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `PORT` | Порт Node.js-сервера | `3000` |
| `AI_PROVIDER` | `auto`, `openrouter` или `ollama`; выбирает параметры API | `auto` |
| `STORE_KIND` | `memory` или `upstash` | Автовыбор: Upstash при наличии обоих реквизитов, иначе память |
| `UPSTASH_REDIS_REST_URL` | REST-адрес Upstash | Не задан |
| `UPSTASH_REDIS_REST_TOKEN` | Секретный токен Upstash | Не задан |
| `OPENROUTER_API_KEY` | Секретный ключ облачного сервиса; Ollama не требует настоящего ключа | Облако: не задан; Ollama: служебное `ollama` |
| `OPENROUTER_BASE_URL` | Базовый адрес OpenAI-совместимого API | OpenRouter: `https://openrouter.ai/api/v1`; при явном `AI_PROVIDER=ollama`: `http://127.0.0.1:11434/v1` |

Модели для всех четырёх задач закреплены в `shared/config.js`: `OPENROUTER_MODEL` и `OLLAMA_MODEL`.
Переменные `MODEL`, `MODEL_HINT`, `MODEL_ANALYSIS` и `MODEL_VISION` больше не читаются;
старые значения в `.env` или настройках хостинга не влияют на запросы.
Для OpenRouter на хостинге по-прежнему нужен секрет `OPENROUTER_API_KEY`.

Пустые значения считаются незаданными. Для `STORE_KIND` неизвестное значение является ошибкой конфигурации.
Ключи и токены остаются на сервере. Для игрового ответа в OpenRouter передаются секретное слово, вопрос и до шести последних вопросов с ответами;
для подсказки — вся история, ранее полученные подсказки и доступные направления;
для разбора — вся история, подсказки, результат, статистика и допустимые кандидаты на полезный вопрос.
В режиме рисунков передаётся только изображение, без правильного ответа и истории партии со словами.

Клиент использует `POST /chat/completions`, `temperature: 0`, `stream: false` и настройки рассуждений выбранного провайдера.
Модель должна поддерживать соответствующий режим ввода; для рисунков нужен ввод изображений.
Доступность бесплатной модели и квота зависят от OpenRouter и провайдера.

| Задача ИИ | Максимум токенов ответа | Таймаут |
|---|---:|---:|
| Игровой ответ | 32 | 9 секунд |
| Подсказка | 160 | 9 секунд |
| Аналитика | 1000 | 15 секунд |
| Рисунок | 512 | OpenRouter: 15 секунд; Ollama: 30 секунд |

Каждая операция Redis ограничена 2,5 секунды. Текущий ход занимает до 14 секунд по серверным лимитам;
браузер ждёт 20 секунд. Для разбора браузер ждёт 30 секунд: это включает чтение партии,
сохранение отметки, до 15 секунд работы ИИ и сохранение результата.
Для рисунка браузер ждёт 45 секунд: до 30 секунд на локальную модель и время на чтение/запись партии.
Сбой или ограничение квоты ИИ возвращает HTTP 503, не расходуя ход. Ответ «не знаю» от самой модели расходует ход.

## Хранение

Партия содержит секрет, остаток вопросов, историю, сложность, результат, время последнего хода,
список подсказок с временем получения, сохранённый разбор или отметку о его подготовке и внутреннюю версию состояния.
Повторный вопрос раньше чем через 700 мс получает сообщение ожидания без расходования хода.

- `memory`: данные одного процесса, срок жизни один час после сохранения; перезапуск удаляет все партии.
  Не подходит для нескольких экземпляров приложения и Cloudflare Pages.
- `upstash`: JSON под ключом `game:<gameId>`, срок жизни один час после сохранения.
  Новая партия записывается командой `SET ... EX 3600` через REST. Обновления используют Lua-скрипт через `EVAL`,
  который атомарно проверяет версию и сохраняет новое состояние со сроком жизни.
  Ошибки чтения или записи возвращаются как HTTP 503, без ложного сообщения об успешном сохранении.

Параллельные ходы и запросы подсказок защищены от перезаписи: устаревшее обновление возвращает HTTP 409
с предложением повторить действие. Такая же проверка версий действует в памяти.
Старые партии без списка подсказок и версии поддерживаются до истечения их срока жизни.

Для рисунков сохраняются только последнее предположение, обратная связь и число попыток.
Изображение остаётся в памяти страницы и передаётся модели при нажатии «Угадай».
Состояние игры в браузере не восстанавливается после перезагрузки страницы.

## Render

Используется `render.yaml`: установка `npm install`, запуск `npm start`, Node.js 22.
В настройках сервиса нужно задать `OPENROUTER_API_KEY`, `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN`.
В конфигурации выбран `STORE_KIND=upstash`. Health check `/` проверяет доступность страницы, а не внешних сервисов.

## Docker

```powershell
docker build -t guess-game .
docker run --rm -p 3000:3000 --env-file .env guess-game
```

Перед запуском создать `.env` из `.env.example` и заполнить настройки. Сервер внутри контейнера слушает `0.0.0.0:3000`;
при изменении `PORT` нужно изменить и проброс порта.

## Cloudflare Pages

Подключить репозиторий к Pages, корень проекта — корень репозитория, выходная папка — `public`, команда сборки не требуется.
Pages собирает обработчики из `functions/` вместе с импортируемыми модулями `shared/`.
Для Pages использовать `STORE_KIND=upstash`, задать адрес Redis, токен и ключ OpenRouter.
Production и Preview настраиваются отдельно; `.env` с компьютера на хостинг не переносится.

Локальная проверка при установленном Wrangler: `wrangler pages dev public`.
Для этого окружения локальные секреты можно задать в `.dev.vars`, используя имена из `.env.example`.
Wrangler не является зависимостью приложения.

## Проверки

```powershell
npm test
```

Проверить синтаксис всех серверных/браузерных модулей и встроенного скрипта HTML:

```powershell
npm run check
```

Единая команда для технической проверки:

```powershell
npm run verify
```

В GitHub Actions настроен запуск этой команды на Linux и Windows при push в `main`/`dev` и pull request.
Установка npm-зависимостей для проверки не требуется. Эти задания не обращаются к реальным ИИ-сервисам и не публикуют приложение.

Проверки используют встроенный `node:test`, реальные обработчики обеих платформ, временный HTTP-сервер и подмену OpenRouter/Redis.
Секреты и сетевые запросы к внешним сервисам для тестов не нужны.

Эти тесты проверяют интеграцию, валидацию, сохранение и ошибки. Они не подтверждают качество ответов живой модели.
Для оценки качества нужен ключ OpenRouter и отдельный прогон на реальных вопросах, партиях и рисунках.
При исправлении интеграции с Ollama выполнен отдельный прогон на настоящей `gemma4:e2b`: две подсказки,
вопрос с известным ответом, разбор с повторным чтением и обработка тестового рисунка.
Это не заменяет полноценную оценку качества на наборе реальных детских вопросов и рисунков.
Перечень проверок перед публикацией — [docs/release-checklist.md](docs/release-checklist.md).
